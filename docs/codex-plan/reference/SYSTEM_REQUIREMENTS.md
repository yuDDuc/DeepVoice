# AVRT Studio system requirements (source of truth)

## Goals
Build an integrated authenticated full-stack application for English ⇄ Vietnamese speech/text translation and dialogue: realtime microphone, upload/audio file, subtitles (partial/stable/confirmed/corrected), optional streaming TTS, translation verification, speaker-specific vocabulary/context memory, accent/code-switch adaptation, prediction-assisted latency, bidirectional turn-taking, local/cloud routing and exportable session history. Prioritize model independence, testability, security and eventual migration onto a Linux/ARM compute module.

## Non-negotiable requirements
1. **Functional mock-first app**, as well as actually runnable model adapters. UI controls must call real APIs, not static demo arrays. Nonconfigured genuine AI/cloud/payment capability must be clearly labeled unavailable/configure-first, not silently fabricated.
2. **Model plugin registry** with independent roles: ASR_EN, ASR_VI, MT_EN_VI, MT_VI_EN, TTS_EN, TTS_VI, VERIFIER, PREDICTOR, SPEAKER_EMBEDDER (optional). Per role source (`hf_hub`, `hf_remote`, `local`, `mock`); ID/path, revision, runtime engine, dtype, quantization, device, audio/text formats, declared shapes, sample rate, channels, language, chunk/stride limits and adapter kwargs from env. Roles may share weights when compatible. Preflight and diagnostics before activation. Never execute untrusted model code by default.
3. **Model lifecycle**: registry metadata/status; HF gated credentials handled server-side; model chosen on first use or warmup, fetch lazily from HF Hub with cached revision/persisted volume and progress/events, memory-aware load/unload; local custom weight folder and adapter manifest; no repo/model hardcoding in pipeline. Remote inference: provider-supported tasks only; do not assume all tasks support true stream or that hosted model is warm/available.
4. **Realtime**: secure authenticated WS session, binary audio protocol with sequence ids/time info/flow control, chunk buffering, resampling, VAD, interim and final ASR; reorder-safe stable/confirmed/corrected translated segments; adaptive wait/latency policy; fast verifier for numerical values, units, negation, named entities; optional semantic verifier and correction; TTS never speaks unverified high-risk provisional content. Speech echo mitigation, cancellation, fallback and explicit error states. Two directions EN/VI, manual PTT and optional auto-detection. Accent/code-switch and prediction as feature-flagged adapters with measurable A/B tests.
5. **Metrics in active inference**: psutil CPU percent, process/system RSS, GPU utilization and VRAM if accessible via NVML; per-stage times, end-to-end latency p50/p95, RTF, chunk queue sizes, FPS not relevant. Distinguish entire device GPU utilization from per-process VRAM. On HF remote never claim visibility into remote GPU utilization. Server-side windowed aggregation, limited sampling interval, authenticated WS/SSE for client charts, proper fallback on CPU-only.
6. **Accounts and RBAC**: signup/signin/signout, email verification optional configurable in dev, password hash (Argon2id), cookie tokens, short access + rotating refresh, CSRF, rate limits, user/admin, resource ownership, audit trail. Do not leak secrets to frontend or browser. Mongo indexes/TTL. Session data retention and deletion options; opt-in for audio retention and speaker memory; privacy controls.
7. **Billing**: subscription plan and credits ledger (integer accounting, no floats); order/payment/transactions with provider idempotency, secure signed webhook, expiration, cancellation, reconciliation, refund/manual-review states. Mock gateway for development. VietQR bank-transfer integration through payOS as first provider; SePay adapter optional; Google Pay enabled only with an actual supported PSP and eligible merchant, otherwise disabled with instructions. QR amount + transfer message + bank details; validate amount/reference, not screenshots or client-provided `paid=true`. Mongo replica-set transaction on wallet/ledger/orders; outbox for cross-service side effects and recovery. Sandbox/test without real charges.
8. **Frontend** responsive modern dashboard: marketing/landing, login/register, live translator (both directions), upload translator, subtitles/dual transcript, session history, model registry and per-role health, metrics panel while translating, account, billing/plans/topup/QR/status, admin operations, FAQ/privacy/consent. Accessibility, dark/light, skeleton/empty/error/loading states.
9. **Infrastructure** Next.js + TypeScript + Tailwind + shadcn/ui; Python FastAPI + Pydantic settings, distinct inference worker process, Redis, Mongo replica set, Docker Compose CPU default and optional GPU profile. Persistent model and Mongo volumes; Compose healthchecks; migrations/index bootstrap; CI tests. Use strict env validation. OpenAPI specs. Browser media HTTPS/localhost; Kubernetes not required.
10. **Diagrams** Mermaid ERD for Mongo collections (logical relations), role/access-flow chart, inference streaming sequence diagram, payment signed-webhook sequence, model-loading state diagram. Store in `docs/architecture/` and render in README or docs route.

## Explicit anti-requirements
- No fake payment success, no hardcoded HF secret or bank account, no production UI pretending to support Google Pay until configured.
- No arbitrary execution/upload of custom Python model files without trusted-user admin opt-in and sandboxing guidance; prefer safetensors/ONNX/GGUF and existing adapters.
- No default auto-training or fine-tuning on unverified transcripts; retain speaker memory only with consent.
- Do not modify model weights or rewrite model-specific tensor shapes behind the user's back.
- Do not hide incompatible models, unavailable CUDA or missing licenses; show actionable preflight errors.
- Avoid blanket DB transactions around slow network/payment calls; keep DB transactions short.

## UI/UX principles
Default language Vietnamese; EN translation-ready. Clear distinction "live provisional" vs "confirmed". Explain where execution happens (Local CPU/GPU, HF Hub cached locally, HF Remote, custom local). Do not fake metrics. Display active role/model/revision/latency and cost/fallback. Admin changes requiring process restart should have restart-required indicator. User-level inference settings only within safe bounds and admin policies.

## Acceptance philosophy
For each phase create real files, tests, docs, run commands (or clearly explain environment blockers). Unit/integration tests use mocks; optional real HF/payment tests are gated by env and secrets. Do not mark complete until checks pass. Final phase report includes changed file paths, tests performed, known risks and how to reproduce.
