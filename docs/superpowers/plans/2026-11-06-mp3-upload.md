# MP3 Upload Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let users upload MP3 files by decoding them in the browser into the WAV format already accepted by the API.

**Architecture:** Add a focused browser audio utility that decodes MP3 using Web Audio API and serializes mono PCM16 WAV. Keep selected WAV files unchanged and continue using the existing upload endpoint; configure upload duration independently from streaming, with a 60-second default.

**Tech Stack:** Next.js, TypeScript, Web Audio API, existing FastAPI upload endpoint.

---

### Task 1: Add browser MP3-to-WAV conversion

**Files:**
- Create: `frontend/lib/audio.ts`

- [ ] **Step 1: Implement the conversion helper**

Add `mp3ToWav(file: File): Promise<File>` in `frontend/lib/audio.ts`. It must:

1. Construct an `AudioContext`, call `decodeAudioData(await file.arrayBuffer())`, and always close the context in `finally`.
2. Reject audio with zero channels or no samples.
3. Mix all decoded channels into one mono `Float32Array` by averaging each channel's sample at each frame.
4. Encode that mono array as a valid 44-byte-header RIFF/WAVE PCM format, one channel, 16 bits per sample, at `AudioBuffer.sampleRate`. Write samples little-endian, clamp to `[-1, 1]`, scale negative samples by 32768 and non-negative samples by 32767.
5. Return a `File` containing the encoded bytes, with a `.wav` filename derived from the original MP3 filename and MIME type `audio/wav`.
6. If decoding fails, throw a clear error that identifies the browser could not decode the MP3.

- [ ] **Step 2: Type-check the helper**

Run: `cd frontend; npm run typecheck`

Expected: TypeScript exits with code 0.
